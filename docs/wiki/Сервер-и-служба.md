# Сервер и служба

Чтобы ферма работала постоянно и сама запускалась после перезагрузки, на Linux
её запускают как службу systemd.

## Служба systemd

В репозитории лежит шаблон
[`deploy/botfarm.service`](../../deploy/botfarm.service).

1. Скопируйте его рядом под своим именем. Файлы `*.local.service` git
   игнорирует, поэтому личные адреса и пути не попадут в репозиторий:

   ```bash
   cp deploy/botfarm.service deploy/botfarm.local.service
   ```

2. В копии замените:
   - `YOUR_USER` — на пользователя, от которого будет работать ферма (не root);
   - `/opt/SteamGiftBot` — на путь к проекту (два места);
   - `192.168.1.10` — на свои адреса, например `192.168.1.10,100.64.0.5`.
3. Задайте пароль панели, если ещё не задали:
   `env/bin/python -m steamgiftbot.farm --set-password`.
4. Установите и запустите службу:

   ```bash
   sudo cp deploy/botfarm.local.service /etc/systemd/system/botfarm.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now botfarm
   ```

### Управление

```bash
systemctl status botfarm                 # работает ли
sudo systemctl restart botfarm           # после обновления кода
sudo systemctl stop botfarm              # остановить
journalctl -u botfarm -f                 # лог в реальном времени
journalctl -u botfarm --since "-1 hour"  # лог за последний час
```

Настройки, изменённые в панели, перезапуска не требуют. Перезапуск нужен
только после `git pull`. Если ферма упадёт, systemd поднимет её через 30
секунд (`Restart=always`).

Если раньше бот для командной строки работал как отдельная служба (например,
`steamgiftbot.service`), выключите её: `sudo systemctl disable --now
steamgiftbot`. Ферма сама запускает SteamGifts, и два процесса на одном
аккаунте будут мешать друг другу.

## Фаервол

Если панель открывается на самом сервере (`curl http://адрес:8092/`), а с
других устройств нет, порт закрыт фаерволом.

**ufw (Ubuntu):**

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8092 proto tcp comment 'BotFarm panel'
sudo ufw allow in on tailscale0          # если используете Tailscale
```

Узнать, что запросы блокируются, можно в `/var/log/ufw.log`: там будут строки
`[UFW BLOCK] … DPT=8092`.

**firewalld (Fedora, CentOS):**

```bash
sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=192.168.1.0/24 port port=8092 protocol=tcp accept'
sudo firewall-cmd --reload
```

**Windows:** «Брандмауэр Защитника Windows» → «Дополнительные параметры» →
«Правила для входящих подключений» → новое правило для порта TCP 8092, профиль
«Частный».

## Несколько адресов

`--host` принимает несколько адресов через запятую, и на каждом ферма
открывает свою копию панели. Если какого-то адреса ещё нет (Tailscale
поднимается позже сети), ферма повторяет попытку каждые 15 секунд и пишет об
этом в лог один раз.

## Резервные копии

[`scripts/backup-farm.sh`](../../scripts/backup-farm.sh) упаковывает
`farm.json`, `config.ini` и файлы состояния в `backups/botfarm-ГГГГММДД-ЧЧММСС.tar.gz`.
Архивы доступны только владельцу и хранятся 14 последних (переменная `KEEP`).

Ежедневный запуск через cron (`crontab -e`):

```
27 4 * * * /opt/SteamGiftBot/scripts/backup-farm.sh
```

> В архивах лежат живые cookie и токены. Не выкладывайте их и не храните в
> общих папках.

**Восстановление:** остановите службу, распакуйте нужный архив в папку
проекта (`tar -xzf backups/botfarm-….tar.gz`) и запустите службу снова.

## Обновление

```bash
cd /opt/SteamGiftBot
git pull
env/bin/pip install -r requirements.txt
sudo systemctl restart botfarm
```

Перед обновлением полезно сделать резервную копию: `scripts/backup-farm.sh`.
